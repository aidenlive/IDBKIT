v1.0 · zero dependencies

Browser storage, without the ceremony.

idbkit is a typed, promise-based toolkit for IndexedDB. Schema migrations, a fluent query builder, pagination, transactions, and backup — mapped one-to-one to the database underneath, never hidden.

Try the playground Read the docs
$ npm install idbkit
What you get

Everything you actually build, already typed.

The primitives map straight to IndexedDB concepts, so there's no new mental model — just the rough edges removed.

End-to-end types

Describe your stores once. Get inference on keys, values, indexes, and query results across every call — autocomplete that actually knows your data.

schema.ts 
interface AppSchema extends Schema {
  users: {
    key: string;
    value: User;
    indexes: { byEmail: string };
  };
}

const db = await openDatabase<AppSchema>({
  name: "app",
  version: 1,
  stores: {
    users: {
      keyPath: "id",
      indexes: { byEmail: { keyPath: "email", unique: true } },
    },
  },
});

Fluent queries

Range operators, filters, ordering, and limits read like a sentence — and pick the fastest execution path for you.

Automatic migrations

Declare the target schema; idbkit reconciles stores and indexes. Write data backfills only when you need them.

Atomic transactions

Span multiple stores in one transaction. Throw to roll back — partial writes never happen.

Real pagination

Offset pages with totals, or keyset pages that stay O(pageSize) no matter how deep you scroll.

Backup & restore

Snapshot the whole database to a plain object or JSON, import it back, or reset to a clean slate.

Lean & native

~13 KB gzipped, fully tree-shakeable, zero runtime dependencies. ESM, CJS, and a drop-in script build.

By example

Small surface, real power.

example.ts 
import { openDatabase, uuid } from "idbkit";

const db = await openDatabase({
  name: "notebook",
  version: 1,
  stores: { notes: { keyPath: "id" } },
});

await db.store("notes").add({
  id: uuid(),
  title: "Hello",
  body: "First note",
  createdAt: Date.now(),
});

const note = await db.store("notes").get(someId);
// Highest-priority open tasks, newest first, capped at 10.
const urgent = await db
  .store("tasks")
  .query()
  .index("byPriority")
  .aboveOrEqual(2)
  .filter((t) => !t.done)
  .reverse()
  .limit(10)
  .toArray();

// Keyset pagination — cheap at any depth.
const page = await db.store("tasks").paginateKeyset({
  pageSize: 50,
  after: lastCursor,
});
// Debit, credit, and log — all or nothing.
await db.transaction(["accounts", "ledger"], "readwrite", async (tx) => {
  const accounts = tx.store("accounts");
  const from = await accounts.get("a");
  const to = await accounts.get("b");
  if (from.balance < 100) throw new Error("Insufficient funds");

  await accounts.put({ ...from, balance: from.balance - 100 });
  await accounts.put({ ...to, balance: to.balance + 100 });
  await tx.store("ledger").add({ id: uuid(), amount: 100 });
});
// Threw? The whole transaction rolls back.

API at a glance

The whole surface on one screen.

Entry point What it does
openDatabase() Open, create, and migrate a typed database.
db.store(name) Typed store: get, getMany, getAll, count, has, add, put, update, delete, clear.
store.bulkAdd / bulkPut / bulkDelete Atomic batch writes in a single transaction.
store.query() Fluent builder: equals, between, startsWith, filter, map, reverse, limit, paginate.
store.index(name) Look up and range over a named or compound index.
store.iterate() Cursor walk with stop / update / delete directives.
store.paginate / paginateKeyset Offset pages with totals, or O(pageSize) keyset pages.
db.transaction() Atomic multi-store transactions with rollback and retry.
uuid / ulid / timestampKey / counter Key generators, including sortable ULIDs.
db.export / import / restore / reset Snapshot, restore, and clear the database.
withRetry() Exponential backoff with jitter for transient failures.
